## What you'll be able to do

- Embed a document collection, store it in a vector database and search it by meaning with metadata filters.
- Build a RAG pipeline that parses PDFs and web pages, chunks them, retrieves passages and answers with citations.
- Make the system say "I can't find that" when the documents do not contain the answer.
- Improve retrieval with BM25 hybrid search, reciprocal rank fusion, reranking and query rewriting.
- Measure retrieval with recall@k and MRR and answers with faithfulness and relevance, then fix the biggest failure first.
- Judge whether RAG, long context, fine-tuning or graph-based retrieval fits a problem.

## Before you start

You should be able to call a model API from Python ([Calling LLM APIs](#l1-llm-apis)), get validated JSON back ([Structured outputs and function calling basics](#l1-structured-outputs)) and run a small eval over a golden dataset ([Your first evals](#l1-first-evals)). The idea of embeddings as vectors of meaning from [Just enough machine learning](#l0-ml-concepts) is all the maths this level needs.

## How to work through this level

Take the four core modules in order, since each one builds on the last. In each module, do the Start here resources, then spend most of your time on Practice. Use one document set for the whole level, such as a public documentation site or a folder of PDFs you care about, so your practice code grows into the project. Open Go deeper resources when an exercise raises a question.

Build [Docs Q&A with citations](#p2-docs-qa) in the last one and a half to two weeks; much of it reuses your practice code. Leave real time for evaluation and error analysis, because they tell you which change to make next. The optional [Knowledge graphs and GraphRAG](#l2-graphrag) module suits you if your questions span a whole corpus or depend on how entities connect. Everyone else can skip it and come back later.

## Milestone

You have finished Level 2 when your Docs Q&A system gives cited answers and you can show its quality with numbers.

- [ ] Your system answers questions over at least 50 pages of real documents, with citations that lead to the source passage.
- [ ] It refuses at least 7 of the 8 unanswerable questions in your eval set.
- [ ] Retrieval uses hybrid search and a reranker, and a table shows what each one added to recall@5.
- [ ] One command runs your eval and prints recall@k, MRR, faithfulness and answer relevance.
- [ ] A short written error analysis names the main failure types and what you changed because of them.
