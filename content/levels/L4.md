## What you'll be able to do

- Build agents as graphs with typed state, checkpoints, interrupts and streaming in LangGraph.
- Compare the major agent SDKs on concrete criteria and build the same agent in two of them.
- Choose between single-agent and multi-agent designs using your own measurements of accuracy and token cost.
- Pause risky actions for human approval, resume durable runs after a restart, and keep an audit trail.
- Ship a support triage workflow that classifies, researches and drafts, then waits for a person before anything is sent.

## Before you start

Finish [Level 3](#L3) first, especially [The agent loop](#l3-agent-loop), [Workflows and agent design patterns](#l3-workflow-patterns) and [Memory and context engineering](#l3-memory-context). You should have built a tool-calling agent by hand, because that is how you will see what a framework does for you. The project also searches a knowledge base, so review [Building a RAG pipeline](#l2-rag-pipeline), and be comfortable with async code and Pydantic from [Python for AI engineering](#l0-python-for-ai).

## How to work through this level

Start with [Stateful agents with LangGraph](#l4-langgraph), because state, checkpoints and interrupts come up again in every later module. Then work through [Agent SDKs compared](#l4-agent-sdks), [Multi-agent systems](#l4-multi-agent) and [Human in the loop](#l4-human-in-the-loop) in that order. Spend about a third of each module's hours on resources and the rest on practice. Start the project once Human in the loop is done, around week 3, and give it two full weeks.

Two optional specialisations add about one week each, and both are easier after the core modules. Take [Coding agents](#l4-coding-agents) if you want to build or customise agents that read, edit and test code. Take [Browser and computer-use agents](#l4-computer-use) if your agents must operate websites or desktop apps that have no API.

## Milestone

You have finished this level when your support triage workflow runs end to end with a human gate and survives a restart.

- [ ] Your triage workflow classifies, researches, drafts and pauses for approval on at least 20 sample tickets.
- [ ] Killing and restarting the process mid-run loses no pending approvals, and each approved reply is sent exactly once.
- [ ] A reviewer can approve, edit or reject a draft, and every decision appears in an audit log.
- [ ] You have built the same small agent in two SDKs and written down which you would choose and why.
- [ ] You can explain, with numbers from your own tests, when a multi-agent design beat a single agent and when it did not.
