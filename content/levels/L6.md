## What you'll be able to do

- Serve an agent behind a streaming API, with long runs in background workers or durable workflows that survive crashes.
- Package, configure and deploy an agent service with CI that blocks quality regressions and canaries prompt changes.
- Route model calls through a gateway with timeouts, fallbacks, per-user budgets and prompt caching.
- Measure cost and latency per completed task and cut them without losing eval quality.
- Decide when an open, fine-tuned model is worth running yourself, and serve one (optional module).
- Keep up with the field and present your work through posts, demos and open-source contributions.

## Before you start

You need a working agent with evals, tracing and basic guardrails, which is what you built in [Level 5](#L5) and the [Harden an agent](#p5-harden-agent) project. You should be comfortable with FastAPI from [Web APIs, HTTP and JSON](#l0-apis-and-http) and with Docker and GitHub Actions from [Git, the command line and Docker](#l0-dev-tooling). Checkpointing from [Stateful agents with LangGraph](#l4-langgraph) helps too. [Evals in depth](#l5-evals-in-depth) and [Observability and tracing](#l5-observability) matter most, because this level uses your eval suite as a deployment gate and your traces as the source of cost data.

## How to work through this level

Start with [Deploying agent applications](#l6-deployment), then [Reliability, latency and cost](#l6-reliability-cost), since the gateway sits on top of the service you deploy. Do the practice exercises against your Level 5 agent rather than toy code, so each exercise becomes part of [the project](#p6-production-deploy). A good split is roughly a third of your time on resources, a third on practice and a third on the project.

Fit [Staying current and building a portfolio](#l6-staying-current) around the other work. Set up your reading slot in week one and write your post once the project ships. [Open models, fine-tuning and serving](#l6-open-models) is optional. Take it if you handle privacy-sensitive data, expect very high call volumes or want ML engineering roles, and skip it if you plan to stay on hosted APIs for now. [Agent system design and capacity planning](#l6-system-design) is also optional and suits people heading for senior or architect roles. It puts numbers on quotas, latency, cost and memory, using companion exercises from the Agentic AI Mastery guide. When interviews come up, use the separate [Interview prep](#interview) section, which sits outside the levels. After this level, [the capstone](#capstone) asks you to ship a production agent end to end.

## Milestone

Your agent runs at a public URL, survives failures, stays within budget and changes only when evals pass.

- [ ] A public URL streams agent progress over SSE, and long runs return a job id and finish in the background.
- [ ] Killing the worker mid-run neither loses the run nor repeats completed model calls.
- [ ] All model calls go through a gateway with a working cross-provider fallback and per-user budgets.
- [ ] Prompt caching is on, and a dashboard shows cached tokens and cost per completed task.
- [ ] CI blocks a pull request whose prompt change lowers the eval score, and a canary compares new and current prompts on live traffic.
- [ ] You have published a write-up and a short demo of the deployed agent.
